# 提前终止的离线模拟

这组脚本用已经记录下来的智能体运行记录，模拟 EarlyEval 式的提前终止：在一次运行进行到一半时，根据智能体到目前为止的行为预测这道题最终能否解出；一旦有把握，就停止这次运行。模拟不调用任何 API，只回答两个问题：能省下多少 token，以及会不会因此选错父代。

| 文件 | 作用 |
| --- | --- |
| `trajectories.py` | 解析 DGM / HGM 的对话记录（`<题目>.md`）和结果（`<题目>.json`，也读压缩后的 `.gz`），并读出每次模型调用的 token 用量（含前缀缓存命中的 token）。支持 OpenAI Responses 和经 vLLM 的 Chat Completions 两种记录格式 |
| `features.py` | 提取前缀特征：查看、编辑、运行命令和测试的次数，报错与测试通过/失败的信号，编程语言等。只用到当前这一步为止的信息 |
| `simulate.py` | 训练校准过的梯度提升分类器，在留出数据上逐步模拟提前终止，输出节省比例（全部 token，以及 GPU 实际要算的未缓存输入加输出）和预测准确率；有多个智能体时还输出智能体排名的 Spearman 相关系数，以及最好的智能体是否不变 |
| `test_early_stop.py` | 解析器和特征的单元测试 |

## 运行

```bash
python simulate.py PRED_DIR=AGENT_NAME [PRED_DIR=AGENT_NAME ...]
python simulate.py --run-dir <HGM 输出目录>/hgm-fixed-r0 [--split time|agent] [--folds 5]
```

只有一个智能体时，按题目分组做交叉验证。有多个智能体时默认按时间切分（`--split time`）：子代按创建顺序分成若干块，每一块只用更早的块训练出的模型来预测，这才是在线提前终止实际能拿到的信息。`--split agent` 按智能体分组，会用到更晚的子代，结果偏乐观。

服务器上实验用的 venv（`~/efficient-rsi/venv`）装有 sklearn，可以直接在那里运行，不必把记录拷下来。

## 第二次结果：HGM 修复版第 0 次运行，本地 Qwen3-Coder，Polyglot（2026-10-20）

数据是 hgm-fixed-r0 的 37 个子代、672 条有工具调用的运行记录，解出率 21.7%（全部猜未解出的准确率 78.3%）。按时间切分成 5 块，最早的一块只用于训练，其余 525 条用于测试。

- 前缀分类器的区分能力明显好于第一次：前 5 步的 ROC AUC 在 0.76 到 0.81 之间（第一次是 0.65 到 0.73）。
- 成功预测仍然从未达到 0.8 以上的置信度，所有提前终止都是“预测失败”，所以表中 s 不起作用。
- 失败阈值 f 决定取舍：

| f | 提前终止的比例 | 终止判断的准确率 | 省下的 GPU token（未缓存输入＋输出） | 估计的解出率（真实 22.3%） | 智能体排名 Spearman | 最好的智能体是否不变 |
| --- | --- | --- | --- | --- | --- | --- |
| 0.95 | 6.7% | 97.1% | 14.7% | 22.1% | 0.997 | 是 |
| 0.90 | 31.8% | 94.0% | 34.6% | 20.4% | 0.961 | 否 |
| 0.85 | 55.6% | 91.4% | 73.2% | 17.5% | 0.874 | 否 |
| 0.80 | 78.9% | 87.2% | 89.2% | 12.2% | 0.582 | 否 |

- 省下的 GPU token 比例高于全部 token 的比例（f = 0.95 时 14.7% 对 8.6%），说明注定失败的长运行后期，未缓存的输入更多。
- 自我改进关心的是选择，而不是单条记录的准确率。f = 0.9 时虽然省下约三分之一，但最好的智能体已经变了；只有 f = 0.95 能保持排名。下一步需要在 0.90 到 0.95 之间细化阈值，并按实际的选择规则（Beta 下界）而不是平均解出率检查最终选择是否改变。
- 仍未计入提前终止后省下的测试和容器时间。

## 第一次结果：DGM 初始智能体，Polyglot（2026-10-11）

数据是 DGM 仓库自带的初始智能体在 Polyglot 上的 225 条运行记录（模型为 o3-mini），其中 221 条有工具调用，解出率 14.5%。“全部猜未解出”的准确率就有 85.5%，下面的数字都要和这个基线比较。

- 前缀分类器的区分能力不强：前 5 步的 ROC AUC 在 0.65 到 0.73 之间。
- 成功预测从未达到 0.8 以上的置信度，所有提前终止都是“预测失败”。
- 失败阈值设为 0.9 时，45.7% 的运行被提前终止，终止时的判断准确率为 94.1%，节省 48% 的 token；代价是估计的解出率从 14.5% 降到 11.8%。
- 按编程语言做留一法测试（只用于检查代码，不代表真实情形）时，准确率降到基线以下，说明遇到训练中没见过的分布时，提前终止可能有害。

这批数据只有一个智能体、32 个正例，无法检验排名能否保持。需要等 HGM 运行产生多个子代的记录后，再做留一智能体的测试。

模拟只统计了模型调用的 token，没有计入提前终止后省下的测试运行和容器时间。

校准分类器时，交叉验证按轨迹分组，同一条运行的不同前缀不会同时出现在拟合集和校准集里；token 节省比例的分母包含每道题的第一次模型调用。
